# Validation

来源优先级与双来源定义见 `prompts/evidence_standards.md`。不要把证据规则抄进本文件。

## 检查维度

1. 产品代码、市场和名称是否唯一匹配。CSV 列名须符合 `prompts/csv_schema.md`。
2. 来源是否实际支持该字段，是否为官方最新版。
3. 关键动态是否具备两个独立来源。同一机构两个页面不算独立来源。仅官方唯一来源且已说明的，该项可为 `pass`；其余无双来源记关键 `unknown`。
4. 币种、单位、时区、复权方式和统计区间一致；交易币种、产品计价币种、底层暴露币种与报告币种不得混用。
5. 动态字段须有有效 `valid_at`；盘中值与收盘值不得混合。
6. 动态字段是否超过最大允许时效。过期关键项记为 `unknown`，不得标为 `warning`。
7. 公式能否由原始值复算；涉及净值或参考净值的计算须写明分母口径。
8. 缺失值是否显式保留，是否存在猜测填充。
9. 结论是否超出证据范围，相关性是否被误写为因果。
10. 工件 `scope`：`demo_only` / `example` / `archive` 不得作为生产输入。

## 状态裁定

- `pass`：证据充分、口径一致且在时效内
- `warning`：仅非关键限制可披露后继续。不得用于掩盖关键时效过期、关键双来源缺失或其他关键缺陷。关键字段的 `warning` 须附关闭证据后视为已关闭；未关闭不得放行进入 Modeling 或 `act`。
- `fail`：关键错误，停止决策
- `unknown`：证据不足、关键时效过期、或关键动态无合格双来源

输出 Validation Report：检查范围、逐项状态、发现、修正建议、未解决问题和是否允许进入下一阶段。
